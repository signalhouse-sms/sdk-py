================================================================================
                    SIGNALHOUSE PYTHON SDK DOCUMENTATION
================================================================================

INSTALLATION
--------------------------------------------------------------------------------
  pip install signalhouse-sms


INITIALIZATION
--------------------------------------------------------------------------------
  from signalhouse_sms import SignalHouseSDK

  signal_house = SignalHouseSDK(
      api_key="your-api-token",
      base_url="https://v2.signalhouse.io",
  )

  Required options:
    - api_key   (str)  JWT token or service user token for authentication
    - base_url  (str)  API base URL

  The SDK raises a ValueError at initialization if api_key or base_url
  is missing.


PER-REQUEST TOKEN OVERRIDE
--------------------------------------------------------------------------------
  Every SDK method accepts an optional "token" keyword argument to override
  the default api_key for that single request.

  Example:
    response = signal_house.messages.get_messages(
        page=1,
        limit=10,
        token="user-specific-jwt-token",
    )

  The per-request token takes precedence over the api_key provided at
  initialization. The original api_key remains unchanged.


CUSTOM HEADERS
--------------------------------------------------------------------------------
  Pass additional headers via the "headers" keyword argument:

  Example:
    response = signal_house.numbers.get_phone_numbers(
        page=1,
        limit=20,
        headers={"X-Request-Id": "req_abc123"},
    )


IDEMPOTENT REQUESTS
--------------------------------------------------------------------------------
  Pass the "idempotency_key" keyword argument to make a create, update or
  delete safe to retry. The SDK sends it as the Idempotency-Key header. A
  retry with the same key and the same request replays the first response,
  marked with the response header Idempotent-Replayed: true, instead of
  running the request again.

  - Use a new key (a UUID is recommended) for each new operation, and reuse
    it only to retry that exact request.
  - Keys are scoped to the authenticated user and kept for 24 hours.
  - Reusing a key for a different request returns 422; retrying while the
    first request is still running returns 409 with Retry-After.
  - The SDK never creates a key for you. GET requests ignore it, and the
    Voice service does not support it.

  Example:
    import uuid

    response = signal_house.subgroups.create_subgroup(
        {"groupId": "G0000001", "subgroupName": "Support"},
        idempotency_key=str(uuid.uuid4()),
    )

AUTH  (signal_house.auth)
--------------------------------------------------------------------------------
  login(email, password, *, token=None, headers=None)
    Login with email and password.

  reset_password(user_id, new_password, *, token=None, headers=None)
    Reset a user's password.

  get_auth_history(*, group_id=None, user_id=None, page=None, limit=None,
      token=None, headers=None)
    Get token login history.

  get_oauth_authorization_url(provider, next=None, email=None,
      link_ticket=None, reauth_ticket=None)
    Build the URL that starts an OAuth sign-in (a browser redirect, not an
    API call). provider: "google", "microsoft", "apple" or "sso" (Enterprise
    SSO; requires email). link_ticket (from create_oauth_link) links the
    provider to the signed-in account instead; the API then returns the user
    to /Settings/Security with a pendingLink to pass to confirm_oauth_link.
    reauth_ticket (from create_oauth_reauth) signs the account in again to
    confirm it's them ("sso" needs no email then).
    Query keys: email, linkTicket, reauthTicket, next (only those set).

  get_oauth_links(*, token=None, headers=None)
    List the caller's sign-in methods. Sends a GET to /auth/oauth/links.
    Returns {"passwordKnown": bool, "links": [{"provider", "email",
    "linkedAt", "lastLoginAt"}]}.

  create_oauth_link(provider, *, token=None, headers=None)
    Start linking "google", "microsoft" or "apple" to the caller's account.
    Sends a POST to /auth/oauth/:provider/link. Requires (and spends) a fresh
    confirm_two_factor_identity. Returns {"linkTicket", "expiresInSeconds"};
    pass the ticket to get_oauth_authorization_url(provider, link_ticket=...).

  create_oauth_reauth(provider, *, token=None, headers=None)
    Start signing in again with a provider linked to the caller's account, to
    confirm it's them. Sends a POST to /auth/oauth/:provider/reauth
    ("microsoft", "apple" or "sso"; Google is refused with 400). Spends nothing. Returns
    {"reauthTicket", "reauthSecret", "expiresInSeconds"} (keep reauthSecret for the confirm call); pass the ticket to
    get_oauth_authorization_url(provider, reauth_ticket=...). The browser
    comes back to /Settings/Security with a single-use pendingReauth (the session that
    started it redeems it with confirm_oauth_reauth) or reauthError.

  confirm_oauth_reauth(pending_reauth, reauth_secret, *, token=None,
      headers=None)
    Finish signing in again with a linked provider. Sends a POST to
    /auth/oauth/reauth/confirm with { pendingReauth, reauthSecret }. pendingReauth
    is the
    single-use value (valid 5 minutes) the create_oauth_reauth round trip returns
    to /Settings/Security with. It counts only for the same account and
    session that started it; 400 when expired or used, 403 for another
    account or session. reauthSecret is the value the create call returned;
    a wrong or missing secret is refused (403) and uses up the re-sign-in.
    Returns: { identityConfirmed } (true when 2FA is off, so it counts as a
    confirmed identity).

  confirm_oauth_link(pending_link, *, token=None, headers=None)
    Finish linking a provider. Sends a POST to /auth/oauth/links/confirm with
    {"pendingLink"}. The provider round trip started with create_oauth_link
    returns the browser to /Settings/Security?pendingLink=...; this links it,
    but only for the account the link was started for. Returns the caller's
    {"passwordKnown", "links"}.

  delete_oauth_link(provider, *, token=None, headers=None)
    Unlink "google", "microsoft", "apple" or "sso" from the caller's account.
    Sends a DELETE to /auth/oauth/:provider/link. Requires a fresh
    confirm_two_factor_identity. 400 when it is the account's only sign-in
    method. Returns the remaining {"passwordKnown", "links"}.

BRANDS  (signal_house.brands)
--------------------------------------------------------------------------------
  get_brands(*, id=None, subgroup_id=None, group_id=None, page=None,
      limit=None, status=None, current_toll_free_carrier=None, token=None,
      headers=None)
    List brands with filters.
    current_toll_free_carrier: with subgroup_id or group_id, True returns only
    toll-free brands that a new toll-free campaign in that group can use
    (those on the group's current toll-free carrier).
    Each toll-free brand carries tollFree.reviewsBusinessOnSubmit (whether
    it's reviewed when it's submitted and keeps its business details from
    then on); when that is true, it also carries the five business fields it
    was submitted with (tollFree's businessStructure, industry, contactEmail,
    contactJobTitle and contactJobLevel) and tollFree.rejectionReason (why it
    was rejected, or null).

  create_brand(brand_data, *, token=None, headers=None)
    Create a new 10DLC brand.

  create_toll_free_brand(brand_data, *, token=None, headers=None)
    Create a new toll-free brand. Its toll-free fields go under tollFree:
    businessRegistrationType, legalEntityType, taxId, countryCode,
    supportPhone, and optional taxIdIssuingCountry, businessDBA and
    businessWebsite.
    Some groups' toll-free brands are reviewed when they're submitted;
    get_toll_free_requirements says whether a group's are. Such a brand also
    needs five tollFree fields: businessStructure (CO_OPERATIVE, CORPORATION,
    LIMITED_LIABILITY_CORPORATION, NON_PROFIT_CORPORATION or PARTNERSHIP),
    industry (AGRICULTURE, AUTOMOTIVE, BANKING, CONSTRUCTION, CONSUMER,
    EDUCATION, ELECTRONICS, ENGINEERING, ENERGY, FAST_MOVING_CONSUMER_GOODS,
    FINANCIAL, FINTECH, FOOD_AND_BEVERAGE, GOVERNMENT, HEALTHCARE,
    HOSPITALITY, INSURANCE, JEWELRY, LEGAL, MANUFACTURING, MEDIA,
    NOT_FOR_PROFIT, OIL_AND_GAS, ONLINE, PROFESSIONAL_SERVICES, RAW_MATERIALS,
    REAL_ESTATE, RELIGION, RETAIL, TECHNOLOGY, TELECOMMUNICATIONS,
    TRANSPORTATION or TRAVEL), contactEmail (a valid email, at most 100
    characters), contactJobTitle (at most 100 characters) and contactJobLevel
    (DIRECTOR, GM, VP, CEO, CFO, GENERAL_COUNSEL or OTHER). Its
    tollFree.countryCode must be "US" or "CA" and its state a 2-letter state
    or province code. Any other group's toll-free brands are refused the five
    fields (400).
    Such a brand stays DCA_PENDING until its business details pass the
    review, which usually takes 1–2 business days, then becomes DCA_ACTIVE;
    if they don't pass, it becomes DCA_REJECTED with tollFree.rejectionReason
    saying why. To fix a rejected brand, create it again with the
    corrections; the rejected one can then be deleted. Its business details
    (companyName, street, city, state, postalCode, country, firstName,
    lastName, tollFree's businessRegistrationType, taxId, countryCode and
    taxIdIssuingCountry, and the five) can't be changed after it's submitted.
    Returns 202 with the new brand (status PENDING_CREATION).

  get_toll_free_requirements(group_id, *, token=None, headers=None)
    Get whether a group's new toll-free brands are reviewed when they're
    submitted, which decides what they need.
    Returns { groupId, reviewsBusinessOnSubmit }. When reviewsBusinessOnSubmit
    is true, a new toll-free brand in the group needs tollFree's
    businessStructure, industry, contactEmail, contactJobTitle and
    contactJobLevel, a tollFree.countryCode of "US" or "CA" and a 2-letter
    state; it stays DCA_PENDING until it's reviewed, and its business details
    can't be changed after it's submitted (see create_toll_free_brand). When
    false, the group's toll-free brands are refused those five fields. 403
    when the caller can't view the group.

  update_brand(brand_id, brand_data, *, token=None, headers=None)
    Update brand information.

  delete_brand(brand_id, *, token=None, headers=None)
    Delete (soft) a brand.

  transfer_brand(subgroup_id, brand_ids, *, token=None, headers=None)
    Transfer brands to a different subgroup.

  get_external_vetting(brand_id, *, token=None, headers=None)
    Get external vetting info for a brand.

  create_external_vetting(brand_id, *, token=None, headers=None)
    Submit brand for external vetting.

  import_external_vetting(brand_id, vetting_provider_id, vetting_id, vetting_token=None, *, token=None, headers=None)
    Import an existing external vetting record (not billable).

  revet_brand(brand_id, *, token=None, headers=None)
    Resubmit brand for vetting.

  get_appeal_history(brand_id, *, token=None, headers=None)
    List identity status appeals for a brand.

  submit_appeal(brand_id, appeal_categories, explanation, *, file=None,
      token=None, headers=None)
    Submit a brand identity status appeal with supporting documentation.
    Uses multipart/form-data automatically.
    appeal_categories: list of strings (VERIFY_TAX_ID, VERIFY_NON_PROFIT, VERIFY_GOVERNMENT)
    explanation: str (max 1024 chars)
    file: file-like object (supported: .jpg, .jpeg, .png, .bmp, .raw, .tiff, .pdf, .docx, .htm, .odt, .rtf, .txt, .xml)

================================================================================
                          MULTIPART REQUESTS
================================================================================

  The following methods use multipart/form-data automatically:

    - signal_house.messages.send_mms(...)
    - signal_house.messages.send_group_message(...)
    - signal_house.landings.create_landing(...)
    - signal_house.landings.update_landing(...)
    - signal_house.brands.submit_appeal(...)

  You do not need to construct multipart form data manually. Pass parameters
  as normal keyword arguments and the SDK builds the form data internally
  using the requests library.


================================================================================
                          QUERY STRING HELPERS
================================================================================

  The SDK automatically constructs query strings from method parameters.
  Any parameter with a None value is excluded, so you only need to pass
  the filters you care about.

  Example:
    # Only sends ?status=FAILED&page=1&limit=50
    messages = signal_house.messages.get_messages(
        status="FAILED",
        group_id=None,     # excluded
        direction=None,    # excluded
        page=1,
        limit=50,
    )


================================================================================
                             VALIDATION
================================================================================

  The SDK validates required parameters client-side before making any HTTP
  request. If a required parameter is missing, None, or an empty string,
  the SDK raises a SignalHouseValidationError immediately -- no network
  request is made.

  Validation errors have:
    - Type:    signalhouse_sms.exceptions.SignalHouseValidationError
    - Message: "Missing required parameter: <field_name>"
    - status:  400


================================================================================
                           ERROR HANDLING
================================================================================

  The SDK uses a standardized response format. Errors are NOT raised --
  they are returned as dictionaries with "success": False.

  Success response:
    {"success": True, "data": {...}, "status": 200}

  Error response:
    {"success": False, "error": "Error message", "status": 400}

  Error types summary:

    Source                    Behavior                              How to Handle
    ---------------------------------------------------------------------------
    Missing required param    Raises SignalHouseValidationError     try/except
    HTTP 4xx/5xx from API     Returns {"success": False, ...}      Check response["success"]
    Network failure           Returns {"success": False, ...}      Check response["success"]


================================================================================
                       COMPLETE INTEGRATION EXAMPLE
================================================================================

  import os
  from flask import Flask, request, jsonify
  from signalhouse_sms import SignalHouseSDK
  from signalhouse_sms.exceptions import SignalHouseValidationError

  app = Flask(__name__)

  signal_house = SignalHouseSDK(
      api_key=os.environ["SIGNALHOUSE_API_KEY"],
      base_url="https://v2.signalhouse.io",
  )

  # Send an SMS notification
  @app.post("/api/notify")
  def notify():
      data = request.get_json()

      try:
          response = signal_house.messages.send_sms(
              sender_phone_number=data["senderNumber"],
              recipient_phone_numbers=[data["recipientNumber"]],
              message_body=data["message"],
              status_callback_url=f"{os.environ['BASE_URL']}/api/delivery-status",
          )

          if not response["success"]:
              return jsonify({"error": response["error"]}), response.get("status", 500)

          return jsonify({
              "messageId": response["data"]["messageId"],
              "status": response["data"]["status"],
          })
      except SignalHouseValidationError as e:
          return jsonify({"error": str(e)}), 400
      except Exception:
          return jsonify({"error": "Internal server error"}), 500

  # Receive delivery status callbacks
  @app.post("/api/delivery-status")
  def delivery_status():
      data = request.get_json()
      print(f"Message {data['messageId']} status: {data['status']}")
      return jsonify({"received": True})

  # List phone numbers with per-request token override
  @app.get("/api/numbers")
  def list_numbers():
      auth_header = request.headers.get("Authorization", "")
      user_token = auth_header.replace("Bearer ", "")

      response = signal_house.numbers.get_phone_numbers(
          page=int(request.args.get("page", 1)),
          limit=int(request.args.get("limit", 20)),
          token=user_token,
      )

      if not response["success"]:
          return jsonify({"error": response["error"]}), response.get("status", 500)

      return jsonify(response["data"])

  # Get message analytics
  @app.get("/api/analytics")
  def analytics():
      response = signal_house.messages.get_analytics(
          start_date=request.args.get("startDate"),
          end_date=request.args.get("endDate"),
          campaign_id=request.args.get("campaignId"),
      )

      if not response["success"]:
          return jsonify({"error": response["error"]}), response.get("status", 500)

      return jsonify(response["data"])

  if __name__ == "__main__":
      app.run(port=3000)


REGISTRATIONS AND REGIONAL REPORTING
--------------------------------------------------------------------------------
A registration is what a jurisdiction (or its provider) requires before a sender
may message. One model covers every jurisdiction: `region` is the jurisdiction
(US, GB, CA, AU; any case of "UK"/"GB"/"GBR"/"United Kingdom" is accepted for GB) and `type` selects the shape of `data`.
Types: TEN_DLC_BRAND, TEN_DLC_CAMPAIGN, TOLL_FREE_BRAND, TOLL_FREE_CAMPAIGN,
SHORT_CODE_BRAND, SHORT_CODE_PROGRAM, SHORT_CODE_LEASE (not available), VIRTUAL_LONG_CODE (UK) and ALPHANUMERIC_SENDER_ID (UK). Kinds: identity, program, sender. Channels: tenDLC, tollFree,
shortCode, virtualLongCode, alphanumeric.

Start with the catalog. GET /registration/catalog?region= returns {region,
jurisdiction, sendingRequiresRegistration, registeredThrough, provisioning, types:[{type, kind,
channel, provider, bundles, quantity:{min,max}, requiresParent, available}]}.
registeredThrough is "registration" (use this API), "brandsAndCampaigns" (the US:
register through the Brands and Campaigns APIs) or null (nothing to register, e.g.
Canada). An unlisted country requires registration and offers no types.
Quote and submit only a type whose `available` is true; other types answer 400.

GET /registration/quotes?region=&type=&quantity= (1-100, default 1) returns
{data:[quotes]}, one quote per capability bundle: {capabilities, quantity,
currency, setupAmount, monthlyAmount, totalSetupAmount, totalMonthlyAmount,
etaDays}. Amounts are integer microdollars; setupAmount/monthlyAmount are per
sender and the totals cover the quantity. groupId is optional and staff-only.

Submit on POST /registration (201) with region, type, subgroupId,
capabilities (one of the type's bundles) and data. Set idempotency_key to make a
retry safe (see IDEMPOTENT REQUESTS). Worked example, UK Virtual Long Code: type "VIRTUAL_LONG_CODE",
capabilities ["SMS"] or ["SMS","VOICE"], data {quantity (1-100), useCases (1-10
strings), voice?}. The voice dossier is required exactly when capabilities
include VOICE: companyName, companyPhone, companyWebsite, companyEmail,
address {line1,line2?,city,postalCode,country}, companyDescription,
campaignName, campaignDescription, optInMethods (WEB|KEYWORD|VERBAL),
optOutKeywords (STOP and UNSUBSCRIBE), callTypes (LANDLINE|LOCAL|INTERNATIONAL),
callsPerDay (1-5), callDurationMinutes (1-10, 15, 30, 45 or 60) and termsUrl.

Worked example, UK alphanumeric sender ID: region "GB", type
"ALPHANUMERIC_SENDER_ID", capabilities ["SMS"], data {requestedSenderId (3-11
letters, digits, spaces, dots or dashes; at least one letter), trafficOrigin
(LOCAL: headquartered in the UK | INTERNATIONAL), trafficType (TRANSACTIONAL |
PROMOTIONAL), companyName, companyCountry, companyWebsite (http/https), industry,
messageExample, senderRelationship? (required when requestedSenderId differs from
companyName)}. quantity is always 1; the quote is one ["SMS"] bundle, 6000000
setup and 6000000 monthly by default. Once the registration is APPROVED,
data.phoneNumbers holds the granted sender (e.g. ["ACME"]); pass it as the sender
to send SMS to UK recipients. The server appends "\nOpt out: sihou.io/o/{code}"
to every message from it, counted in segments and in the estimate.

GET /registration accepts groupId, subgroupId, region, type, kind, status,
parentRegistrationId, phoneNumber (filter to registrations holding this phone
number), brandId, campaignId (RCS agents linked to that brand or campaign;
brand_id and campaign_id in Python), sortBy (createdAt (default), subgroupId, registrationId, region or
status), sortOrder (asc or desc (default)), page and limit (max 100) and returns
{data,totalCount,page,limit}.
Region and status each take one value or a list (str or list[str]; a list is
sent as repeated keys, e.g. status=PENDING_PROVIDER&status=APPROVED).
GET /registration/:registrationId returns
{registrationId, groupId, subgroupId, region, type, kind, channel, provider,
externalId, parentRegistrationId, status, stage, capabilities, submittedAt,
approvedAt, expiresAt, review:{decision,reviewedAt,reason}, data:{...type
fields}, history:[{status,stage,actor,actorType,timestamp,reason}], createdAt,
updatedAt}. For VIRTUAL_LONG_CODE, data also carries phoneNumbers, the numbers
allocated so far. Statuses: DRAFT, SIGNAL_HOUSE_REVIEW, SIGNAL_HOUSE_APPROVED,
SIGNAL_HOUSE_REJECTED, SUBMITTING, PENDING_PROVIDER, NEEDS_INFORMATION,
PAYMENT_REQUIRED (the setup fee could not be funded; retried hourly), APPROVED,
REJECTED, CANCELLED, PENDING_DELETE, DELETED, EXPIRED, RECONCILIATION_REQUIRED.
`stage` is the provider's step inside a status. Never send from a sender whose
registration is not APPROVED.

DELETE /registration/:registrationId cancels a registration (roles api, admin,
developer, user). Allowed from SIGNAL_HOUSE_REVIEW, SIGNAL_HOUSE_APPROVED,
PENDING_PROVIDER, NEEDS_INFORMATION, PAYMENT_REQUIRED and APPROVED (409
otherwise); a type that keeps drafts (RCS_AGENT) can also be cancelled from
DRAFT and SIGNAL_HOUSE_REJECTED. Numbers already allocated stay on the account
and stop sending.

update_registration(registration_id, data) sends PUT /registration/:registrationId
to edit a DRAFT or SIGNAL_HOUSE_REJECTED registration of a type that keeps drafts
(409 otherwise); data is a partial of the type's create fields.
validate_registration(registration_id) sends POST /:registrationId/validate and
returns {valid, errors, warnings}; it writes nothing.
submit_registration(registration_id) sends POST /:registrationId/submit and moves
a draft to SIGNAL_HOUSE_REVIEW, or to SUBMITTING for a type Signal House does not
review first (RCS_AGENT, filed with the provider at once) (400
REGISTRATION_INCOMPLETE with the errors, 409 on a second submit).
launch_registration(registration_id) sends POST /:registrationId/launch: an RCS
agent the carrier partner holds in testing goes to SIGNAL_HOUSE_REVIEW, whose
approval files the launch (409 unless the agent is in testing, Signal House
rejected an earlier request, or every carrier refused one; 400
REGISTRATION_INCOMPLETE with the errors).

Staff only (the admin namespace exists only when the client enables admin, and
enabling it grants no server permission):
POST /:registrationId/review {action:"APPROVE"|"REJECT",reason?}; REJECT needs reason.
POST /:registrationId/corrections {reason,data} saves the type's correctable
fields (VIRTUAL_LONG_CODE: useCases, voice?) while the provider waits; owner,
quantity, bundle and provider order are fixed.
POST /:registrationId/numbers {phoneNumber} allocates a provider-owned number
through the recovery path.
POST /:registrationId/reconcile {externalId} links the provider order that was
placed after an ambiguous submission; never place a second order to retry.
GET /:registrationId/application?format=json returns {filename,contentType,base64};
decode base64 before saving the document.

Regional reporting: GET /message, /message/analytics, /message/analytics/detail,
/message/analytics/by-subgroup, /message/analytics/by-error-code, /message/dnc and
/message/dnc/analytics accept region and regionScopes; GET
/message/analytics/filter-options accepts region only. region is US, GB or CA
(any case of "UK"/"GB"/"GBR"/"United Kingdom" is accepted for GB) as a single value, a repeated parameter or a CSV.
regionScopes is a JSON array of OR-ed branches {region, channels, brandId?,
campaignId?, phoneNumber?} with channels from tenDLC, virtualLongCode, tollFree,
shortCode and p2p; [] matches nothing and omitting both keeps the existing scope.
Example:
[{"region":"US","channels":["tenDLC"],"brandId":["BUS1"]},
 {"region":"GB","channels":["virtualLongCode"],"phoneNumber":["447400123456"]}]
GET /message always accepts them, as do the analytics and DNC reads.

get_analytics, get_analytics_detail, get_analytics_throughput and
get_dnc_analytics accept registration_id (a single id or a list, sent as repeated
registrationId parameters like campaign_id): filter to traffic attributed to these
registrations. Except on
get_analytics_throughput, which has no phoneNumber filter, a phoneNumber filter
takes precedence. get_phone_numbers accepts a single registration_id to list the
numbers provisioned under that registration.

get_analytics_by_subgroup, get_analytics_by_error_code and get_dnc_records accept
registration_id the same way, with the same precedence.
get_messages accepts registration_id: it filters to messages
attributed to those registrations, and a phone_number filter narrows further. Every
method returns 400 when registration_id is combined with campaign_id.

get_analytics_filter_options returns each phone number with its type (TOLL_FREE,
SHORT_CODE, ALPHANUMERIC, VIRTUAL_LONG_NUMBER, and older local-number spellings) and
country (ISO-2), null when unknown. TOLL_FREE, SHORT_CODE and ALPHANUMERIC are channels
by type; a US number of any other type is 10DLC and a non-US one is a Virtual Long Code.
It also returns carriers, a plain array of carrier name strings.

UK sending is SMS only, from a +44 virtual long code to GB mobile recipients; MMS
and group MMS are unavailable. POST /message/estimate accepts a +44 sender
(recipients 10-15 digits) and returns region "GB", or "CA" for a Canadian sender.
A READY alphanumeric sender ID (e.g. "ACME") also sends SMS to UK recipients only;
its estimate includes the opt-out footer.

LANGUAGE EXAMPLE
  catalog = signal_house.registrations.get_catalog("GB")
  quotes = signal_house.registrations.get_quotes(region="GB", type="VIRTUAL_LONG_CODE", quantity=1)
  signal_house.registrations.create_registration({
      "region": "GB", "type": "VIRTUAL_LONG_CODE", "subgroupId": "SGEXAMPLE",
      "capabilities": ["SMS"],
      "data": {"quantity": 1, "useCases": ["Support"]},
  })
  # UK alphanumeric sender ID
  signal_house.registrations.get_quotes(region="GB", type="ALPHANUMERIC_SENDER_ID")
  signal_house.registrations.create_registration({
      "region": "GB", "type": "ALPHANUMERIC_SENDER_ID", "subgroupId": "SGEXAMPLE",
      "capabilities": ["SMS"],
      "data": {"requestedSenderId": "ACME", "trafficOrigin": "LOCAL", "trafficType": "TRANSACTIONAL",
               "companyName": "Acme", "companyCountry": "United Kingdom",
               "companyWebsite": "https://acme.example", "industry": "Retail",
               "messageExample": "Your Acme order has shipped."},
  })
  signal_house.registrations.get_registration("REG2")   # poll until APPROVED; data.phoneNumbers == ["ACME"]
  signal_house.messages.send_sms("ACME", ["447400123456"], "Your Acme order has shipped.")
  signal_house.registrations.get_registrations(region="GB", status="PENDING_PROVIDER")
  signal_house.registrations.get_registration("REG1")
  signal_house.registrations.cancel_registration("REG1")
  signal_house.registrations.admin.review_registration("REG1", "APPROVE")   # enable_admin=True
  signal_house.messages.get_messages(region=["US", "GB"],
      region_scopes=[{"region": "GB", "channels": ["virtualLongCode"]}])
  signal_house.messages.get_analytics_filter_options(group_id="G1", region="GB")


TEMPLATES
--------------------------------------------------------------------------------
Versioned, raw message templates. One namespace, templates, on
/template. list takes an optional channel filter;
create reads the channel from the body. RCS templates answer 404 while
the environment's RCS switch is off. Every call carries groupId: GET in the query string,
JSON writes in the body, the media upload as a form field.

A template has a head {templateId, groupId, channel, name, tag,
archivedAt, draftVersion, publishedVersion, revision,
createdBy, createdAt, updatedAt} and numbered versions
{version, state (DRAFT|PUBLISHED), body, contentHash, publishedAt, ...}. Reads
of one template return {head, version}; lists return {data, total, page, limit}.
The create and update responses add validation ({valid, errors, warnings}, null when the checks could not run), and publish adds warnings. A draft saves even when validation lists errors. On an RCS send, a blocked row carries blockReason, reason and issues.

with summaries that add state and hasUnpublishedChanges.

create creates draft version 1 from name (1-120 chars, unique per
group and channel), body and optional tag (201). get takes version: a
number, "draft" or "published"; omitted reads the published version, else the
draft, and an explicit selector never falls back (404). update saves the
draft from any of name, tag and body; writes apply directly (last write wins)
with no revision guard. Leave tag out to keep it; pass tag=None to clear it.
publish always publishes the current draft and answers 400
{code:"TEMPLATE_INVALID", errors, warnings} for an incomplete draft and 409
{code:"NO_DRAFT"} when there is none. archive takes only groupId. The
409 codes a write can answer are TEMPLATE_ARCHIVED (the template is archived),
TEMPLATE_NAME_TAKEN (another template in the group and channel has the
name), NO_DRAFT (publish with no draft) and DRAFT_CHANGED (publish only: the
draft changed while it was being published; publish again). validate checks
exactly one of body or version and never writes. capabilities returns the
server's block kinds, action types, limits, media rules, time to live ranges,
traffic types per use case and iPhone layout numbers, and with provider
(infobip|sinch) that provider's limits and unsupported features.
upload_media sends multipart fields file and groupId and returns
{mediaId, url, bytes, mimeType, kind, width, height, ...} (201).

The body is the raw RcsTemplateBody {channel:"rcs", contentFormat?, content,
variables, defaults, fallback}; the SDK sends it unchanged and offers no
conversion, duplication or starter helpers. contentFormat defaults to
"content.v1" (content:{blocks}, the only format the API stores and returns);
"google.rcs" sends Google's RBM AgentContentMessage as content, which the API
converts to content.v1. A VIEW_LOCATION suggestion takes latitude/longitude or
an address the API geocodes; geocode_address(group_id=, address=) resolves one
for an author (400 LOCATION_NOT_FOUND, 429 past the group's lookup window, 503
when the server has no geocoding provider). Unknown keys are rejected.
Placeholders are {{key}}; {{sender_name}} is reserved. Writes accept an
idempotency key. Reads (including validate and capabilities) need
admin, developer, api, billing or user; writes need admin, developer or api.

LANGUAGE EXAMPLE
  body = {
      "channel": "rcs",
      "content": {"blocks": [{"id": "b1", "kind": "text", "text": "Hi {{first_name}}"}]},
      "variables": [{"key": "first_name", "type": "text", "required": True}],
  }
  created = signal_house.templates.create(group_id="G1", name="Welcome", body=body,
                                          idempotency_key=str(uuid.uuid4()))
  head = created["data"]["head"]
  saved = signal_house.templates.update(head["templateId"], group_id="G1",
      tag=None)   # None clears the tag; leave it out to keep it
  head = saved["data"]["head"]
  signal_house.templates.validate(head["templateId"], group_id="G1", version="draft")
  signal_house.templates.publish(head["templateId"], group_id="G1")
  signal_house.templates.list(group_id="G1", channel="rcs", state="PUBLISHED")
  signal_house.templates.capabilities(group_id="G1", provider="infobip")
  signal_house.templates.geocode_address(group_id="G1", address="88 Lakeshore Drive, Chicago")
  with open("hero.png", "rb") as image:
      signal_house.templates.upload_media(group_id="G1", file=image, file_name="hero.png")


RCS AGENTS  (signal_house.rcs.agents)
--------------------------------------------------------------------------------
RCS agents under /rcs/agent. An agent links one brand and one campaign, of any
registration type: the campaign's numbers are its SMS fallback, and the brand
and campaign supply the company identity and consent text for the carrier
launch. One brand or campaign can serve many agents. An agent is a registration
(type RCS_AGENT, agentId = registrationId "RCSA" + 10 characters), so the
registrations methods read and edit the same record. 404 while RCS is disabled
for the environment; 400 while the group's rcsEnabled flag is off. To use a new
brand and campaign, create the brand (brands.create_brand), wait until it is
VERIFIED, create the campaign (campaigns.create_campaign), then link them.

The agent: {agentId, groupId, subgroupId, status, registrationStatus, stage,
brandId, brandRef, campaignId, campaignRef, links, agent, consent, useCase,
billingCategory, defaultFallback, excludedCarriers, testers, contact,
testerInvites, carriers, launchable, review, submittedAt, approvedAt, history,
createdAt,
updatedAt}. launchable is true
  when the launch request would be accepted now. brandRef and campaignRef are the
linked records' _ids; brandId and campaignId are their current public ids
(brandId is null until TCR assigns one). links = {brand: {state: OK |
NOT_VERIFIED | MISSING, ...}, campaign: {state: OK | NOT_ACTIVE | MISSING |
NONE, ...}}; a deleted brand or campaign reads MISSING. status: DRAFT,
PENDING_REVIEW, REJECTED, AGENT_CREATING (approved, waiting for the carrier
launch), ARCHIVED.

create(brand_id, campaign_id, agent, consent, use_case, billing_category,
       default_fallback, excluded_carriers, testers, contact)
  Create a draft (201). brand_id is a carrier brand ID, provisional UUID or
  _id; campaign_id (optional until submit) is a campaign ID or _id of that
  brand. The agent's subgroup is the brand's. Blank consent fields fill from
  the campaign. Required: brand_id

list(group_id, subgroup_id, status, brand_id, campaign_id, page, limit)
  List agents, newest first. status takes one value or a list (sent as repeated
  keys). brand_id / campaign_id return the agents linked to that brand or
  campaign. Returns {data, total, page, limit}.

get(agent_id)
  One agent with the live state of its links.

update(agent_id, brand_id, campaign_id, agent, consent, use_case,
       billing_category, default_fallback, excluded_carriers, testers, contact)
  Edit a DRAFT or REJECTED agent. Only the arguments you pass are sent. agent
  and consent merge field by field; other keys replace; campaign_id=None
  unlinks (use_case=None and default_fallback=None clear those fields). 409
  once submitted.

validate(agent_id)
  Returns {valid, errors, warnings} of {field, reason}; writes nothing.

submit(agent_id)
  Create the agent at the carrier partner, with no review first. Needs the full
  profile, use_case and NON_CONVERSATIONAL billing; otherwise 400 with details
  {code: "REGISTRATION_INCOMPLETE", errors, warnings}. The agent moves to
  AGENT_CREATING, then IN_TESTING once the partner reports it ready.

launch(agent_id)
  Request the launch (POST /registration/{agent_id}/launch). The launch
  requirements are checked (a VERIFIED brand, the campaign, the full consent
  with the launch video, the contact) and the agent goes to PENDING_REVIEW;
  Signal House's approval files the launch with the carrier partner. Allowed
  from IN_TESTING, REJECTED and CARRIER_REJECTED (409 otherwise); a failed
  requirement is 400 REGISTRATION_INCOMPLETE.
  The request charges the agent's launch fees: a wallet that cannot cover
  them gets a 402, and the agent stays where it is.
  The agent's launchFees quotes what the next request charges.

archive(agent_id)
  Archive the agent.

resend_tester_invite(agent_id, phone_number=...)
  POST /rcs/agent/:agentId/testers/:phoneNumber/resend. Resend a tester's expired invitation.

upload_asset(agent_id, kind, file, file_name)
  Host a logo (224 x 224 px, 50 KB max) or hero (1440 x 448 px, 200 KB max)
  PNG or JPEG and set it on the draft. kind: "logo" | "hero". Sends
  multipart/form-data fields kind and file. Required: agent_id, kind, file

agent_id is positional; every other argument is keyword-only. Pass
idempotency_key on create to make a retry safe.

LANGUAGE EXAMPLE
  created = signal_house.rcs.agents.create(
      brand_id="B1A2C3D", campaign_id="C4E5F6G",
      agent={"name": "Acme Alerts", "description": "Order alerts from Acme"},
      use_case="TRANSACTIONAL", idempotency_key=str(uuid.uuid4()))
  agent_id = created["data"]["agentId"]
  with open("logo.png", "rb") as image:
      signal_house.rcs.agents.upload_asset(agent_id, kind="logo", file=image, file_name="logo.png")
  check = signal_house.rcs.agents.validate(agent_id)
  if check["data"]["valid"]:
      signal_house.rcs.agents.submit(agent_id)
  signal_house.rcs.agents.list(brand_id="B1A2C3D", status=["DRAFT", "REJECTED"])


RCS MESSAGES  (signal_house.rcs.messages)
--------------------------------------------------------------------------------
  Send through an agent. 404 while RCS is off for the environment, 403 while
  the group's rcsEnabled flag is off, 409 while the agent cannot send yet.

  send(*, agent_id, recipients, template_id=None, template_version=None,
      content=None, content_format=None, traffic_type=None, ttl_seconds=None,
      expire_time=None, fallback=None, status_callback_url=None,
      enable_shortlink=None, is_test=None, simulate=None)
    POST /message/rcs.
    Send to up to 100 recipients. A blocked recipient gets a BLOCKED message and
    the rest still send. Exactly one of template_id or content; at most one of
    ttl_seconds or expire_time. content_format: content.v1 (default) | google.rcs.
    recipients is a list of { phoneNumber, variables, clientMessageId, metadata }.
    fallback is { mode (auto, rcs_only, sms_only), channel (auto, sms, mms), from,
    content: { text, mediaUrls }, validitySeconds }; without content the
    template's fallback, else a generated one, is used. simulate: not_capable |
    ttl_expired | delivered | read, approved testers only.
    Required: agent_id, recipients
    Returns: { requested, enqueued, failed, bulkId, messages } (201)

  validate(*, agent_id, recipients, ...)
